# Бриф для дизайнера — Словарь курса

## 1. Что это и для кого

«Словарь курса» — универсальный модуль учебных карточек внутри образовательной платформы. Не привязан к конкретной дисциплине: одна и та же сущность работает для английского, математики, программирования, дизайна и любого другого предмета. Преподаватель сам решает, какие поля заполнять под свой курс.

**Две роли:**
- **Преподаватель** (teacher) — создаёт, редактирует и удаляет карточки в рамках своих курсов.
- **Студент** (student) — смотрит карточки курсов, на которые записан, и проходит режим повторения (spaced repetition).

**Контекст:** страница открывается из левого сайдбара платформы, занимает основную область (sidebar 260px слева уже есть, header 64px сверху). Т.е. дизайнить нужно **только контентную область**.

---

## 2. Структура одной карточки

Сущность одна на всех. Из полей **обязателен только заголовок**, остальное — на усмотрение преподавателя.

| Поле | Обязательно | Лимит | Назначение |
|---|---|---|---|
| **Заголовок** (Term) | Да | 200 симв. | Само понятие, слово, команда — то, что повторяется |
| **Перевод / краткое значение** (Translation) | Нет | 500 симв. | Короткое пояснение одной строкой. Для языков — перевод, для остальных — краткий смысл |
| **Определение** (Definition) | Нет | 4000 симв. | Развёрнутое объяснение, формула, правило |
| **Пример** (Example) | Нет | 4000 симв. | Пример использования, решение задачи, фрагмент кода |
| **Заметка** (Note) | Нет | 2000 симв. | Частая ошибка, антипример, важно знать |
| **Картинка** (Image) | Нет | 5 МБ, jpg/png/webp/gif | Иллюстрация, скриншот, схема, фото |
| **Теги** (Tags) | Нет | до 20 шт., по 50 симв. | Группировка и поиск |
| **Курс** (Course) | Да (выбор из списка) | — | К какому курсу принадлежит карточка |

**Логика отображения:** в режиме просмотра/повторения **пустые поля не показываются**. Карточка по математике может быть только заголовок + определение + формула в Example. Карточка по английскому — заголовок + перевод + пример. Дизайн обеих карточек должен оставаться визуально цельным, не «дырявым» из-за отсутствия полей.

## 3. Дизайн-система (опираемся на стиль лендинга)

### Палитра
- **Акцент:** `indigo-600` (#4F46E5) → `purple-600` (#9333EA), часто как градиент `135deg`.
- **Дополнительный акцент:** `teal-500` (#14B8A6) для статусов «изучено».
- **Note (заметка):** янтарный — `amber-100` (#FEF3C7) фон + `amber-800` (#92400E) текст.
- **Текст:** `slate-900` основной, `slate-500` вторичный, `slate-400` placeholder.
- **Фон:** `#FFFFFF` карточки, `slate-50` (#F8FAFC) общий бэкграунд страницы.
- **Бордеры:** `slate-200` (#E2E8F0).

### Типографика
- Шрифт: **Inter** (уже подключён).
- Заголовки страницы — 1.5–1.875rem, semibold.
- Заголовок карточки — 1.25–1.35rem, bold.
- Body — 0.9375rem, line-height 1.5.

### Геометрия
- Скругления: `1rem` (16px) для карточек, `0.75rem` (12px) для инпутов и кнопок, `999px` (pill) для тегов и статусов.
- Тени: мягкие, многослойные. `0 10px 30px rgba(15,23,42,0.04)` — базовая, `0 20px 40px rgba(0,0,0,0.08)` — на hover.
- Отступы внутри карточки: 18–24px.

### Кнопки (по аналогии с лендингом)
- **Primary** — градиент indigo→purple, белый текст, тень при hover, transform `translateY(-2px)`.
- **Secondary / Ghost** — белый фон, бордер `slate-200`, текст `slate-700`.
- **Danger** — `red-100` фон, `red-700` текст.

## 4. Что нужно нарисовать (экраны)

### Экран 1 — Главная страница словаря (роль: преподаватель)

**Содержит сверху вниз:**
1. **Хедер страницы** — заголовок «Словарь курса», подзаголовок («Добавляйте термины по своим курсам и управляйте словарём из одного места»), счётчик «N карточек», кнопка «Обновить».
2. **Панель фильтров** — горизонтальная: select «Курс» (или «Все курсы»), поле поиска (с placeholder «Термин, перевод, определение, заметка или тег»).
3. **Кнопка «+ Создать карточку»** — крупная, с градиентом, выраженно акцентная. Можно как floating action button или как заметная кнопка в правом верхнем углу.
4. **Сетка карточек** — `repeat(auto-fit, minmax(320px, 1fr))`, отступы 16–20px.

### Экран 2 — Карточка в списке (общий вид)

Сетка карточек должна красиво смотреться **в трёх состояниях**:
- **Языковая** (короткая): заголовок + перевод + 2 тега. Должна не выглядеть «обрезанной».
- **Полная** (программирование): заголовок + перевод + теги + определение + пример с кодом + заметка.
- **Визуальная** (дизайн): заголовок + картинка + короткая заметка + теги. Картинка занимает значимую часть карточки.

**Внутренняя структура карточки:**
- Шапка: заголовок (крупно), под ним — перевод (если есть, цветной: indigo-700 или teal-600).
- Справа в шапке — pill с названием курса, ниже (для студента) — pill «Изучено» если уместно.
- Теги — pill'ы серые, под шапкой.
- Картинка (если есть) — сразу под тегами, `object-fit: contain`, скруглённый бордер, max-height ~240px.
- Секции «Определение» / «Пример» / «Заметка» — каждая со своим маленьким лейблом-заголовком (uppercase, slate-500, font-size 0.75rem) + текст. Заметка визуально отличается — янтарный фон, выделена.
- Футер: слева хинт («Последнее повторение: …» / «Пока без повторений»), справа кнопки действий («Редактировать», «Удалить» для учителя; «Отметить как изученное» для студента).

**Визуальный приоритет:** заголовок > картинка > перевод > секции > теги > футер.

### Экран 3 — Создание / редактирование карточки

Это самый важный экран UX-wise. Сейчас все поля просто свалены в форму — нужен умный лейаут, который **не пугает и подсказывает**.

**Идеи, которые стоит проработать:**
- **Двухколоночная компоновка** на широких экранах: слева — основные поля и текст, справа — картинка с превью + теги + курс.
- **Поэтапная подача полей**: заголовок и курс — заметно сверху, остальные поля — секциями или с разделителями, чтобы не выглядело как анкета на 10 пунктов.
- **Хинты к каждому полю**: маленьким шрифтом примеры использования (например, под Translation: «для языковых карточек или короткого пояснения»; под Note: «частая ошибка, антипример, важно знать»).
- **Метка «(необязательно)»** — нужна, но визуально не должна доминировать над лейблом. Серым курсивом справа от названия поля.
- **Live-превью карточки** справа от формы — пользователь видит, как будет выглядеть карточка сразу при заполнении. Это **сильно** улучшит UX, потому что снимает страх «что я туда пишу и как это будет смотреться».
- **Загрузка картинки**:
  - Drag-and-drop зона + кнопка «Выбрать файл».
  - При наличии картинки — превью (220×160 примерно) + кнопка «Удалить» / «Заменить».
  - Подсказка про лимиты: «JPEG / PNG / WebP / GIF, до 5 МБ».
  - Состояние загрузки (спиннер + «Загружаем картинку…»).
- **Двухшаговое сохранение**: при создании новой карточки картинку **нельзя загрузить до сохранения** (нет id ещё). Нужно понятно показать это пользователю — зона загрузки disabled с подсказкой «Сначала сохраните карточку, затем добавьте картинку», или сделать единый поток «Создать → автосохранение → можно грузить картинку».

### Экран 4 — Студенческий вид списка

Очень похож на учительский, но:
- Нет кнопки «+ Создать».
- В фильтрах появляется чекбокс «Только изученные».
- На карточках — кнопка «Отметить как изученное» / «Вернуть в повторение» (с цветной индикацией).
- Виден pill «Изучено» с зелёной заливкой.

### Экран 5 — Режим повторения (Study Mode) **— самый интересный для дизайна**

Это режим карточек как в Anki/Quizlet — студент видит одну карточку, пытается вспомнить, открывает ответ, оценивает себя.

**Поток:**
1. Студент жмёт «Начать повторение» в отдельной панели.
2. Открывается «карточный» интерфейс: одна большая карточка по центру.
3. Сверху статистика: «Карточка 3 из 12», «Осталось в очереди: 9», иногда «Следующее повторение: 12.05 14:30».
4. **Лицевая сторона** — только заголовок (крупно, по центру) + теги. Опционально pill курса в углу.
5. Кнопка «Показать ответ» — большая, акцентная.
6. **Обратная сторона** — раскрывается с анимацией flip или slide:
   - Перевод (если есть) — крупно, цветным.
   - Картинка (если есть).
   - Определение, пример, заметка — секциями.
7. После раскрытия — три кнопки оценки: **«Знаю»** (зелёная), **«Сложно»** (жёлтая), **«Позже»** (нейтральная).
8. После выбора — следующая карточка.

**Визуальный язык:** карточка должна ощущаться **физически** — мягкая тень, лёгкий градиент `slate-50 → white`, заметный border-radius (1.25rem). Хочется тактильности.

**Важно:** в режиме повторения **должна быть приятная анимация перехода** между карточками (slide / flip). Это сильно влияет на восприятие «учусь vs работаю».

### Экран 6 — Пустые состояния

Тоже нужно нарисовать:
- **Учитель, нет карточек:** иллюстрация (можно простую), текст «Создайте первую карточку — соберите словарь, формулы или термины своего курса», кнопка «+ Создать карточку».
- **Учитель, фильтры не дают результата:** «Под текущие фильтры карточек нет», кнопка «Сбросить фильтры».
- **Студент, нет карточек:** «Преподаватель ещё не добавил карточки в этот курс».
- **Студент в режиме повторения, очередь пуста:** «Все карточки повторены на сегодня. Возвращайтесь завтра» — приятный, мотивирующий тон.

### Экран 7 — Адаптив

- **Mobile (< 640px):** карточки в один столбец, фильтры — стек, форма создания — одна колонка, study mode — карточка на всю ширину.
- **Tablet (640–1024px):** карточки 2 в ряд.
- **Desktop (> 1024px):** карточки 3 в ряд, в редакторе — двухколоночная компоновка с превью справа.

## 5. Что НЕ нужно дизайнить

- Авторизация, регистрация, профиль — это другой модуль.
- Сайдбар и хедер — уже есть в проекте, не трогаем.
- Модалки подтверждения удаления — стандартные платформенные, договоримся отдельно.
- Любые кастомные иконки — используем `lucide-icons` (бесплатные, уже подключены в проекте).

## 6. Что отдать на выходе

1. **Figma-файл** с экранами 1–7 (можно меньшее количество, но обязательно: список карточек у учителя, форма редактирования с превью, study mode).
2. **3 примера карточки в списке** (языковая / программирование / визуальная) — чтобы было видно, что один компонент работает на разных наполнениях.
3. **Состояния** ключевых элементов: hover/active/disabled для кнопок, focus для инпутов, loading для загрузки картинки.
4. **Mobile-версия** хотя бы для study mode и списка карточек.
5. **Иконография** — выбор иконок из lucide или эквивалентного набора, список используемых.

## 7. Принципы, по которым оценивать

- **Универсальность ≠ безликость.** Карточка с одним полем должна выглядеть так же хорошо, как с шестью.
- **Учитель не должен видеть форму на 10 полей.** Заполнение — лёгкое, с подсказками, опциональные поля заметно отделены от обязательных.
- **Студент в study mode не должен чувствовать корпоративный SaaS.** Это инструмент для учёбы, ощущение должно быть как в Quizlet/Anki — игровое, мотивирующее.
- **Стиль одной семьи с лендингом** — те же градиенты, скругления, шрифт, ощущение качества.
- **Цвет используется осмысленно.** Note всегда янтарный, success всегда зелёный, primary action всегда indigo→purple. Без хаоса.

## 8. Технические нюансы для дизайнера

- Картинки в карточках выводятся как **pre-signed URL** с MinIO, обновляются при каждом GET — поэтому никаких «постоянных миниатюр» предполагать нельзя, всегда учитываем placeholder/skeleton при загрузке.
- В study mode карточка **жёстко по одной**, никаких списков рядом. Раскрытие ответа — кнопкой, не наведением.
- Длинные тексты (определение/пример) могут содержать **переносы строк и пробелы для кода** — нужен `pre-wrap` или его визуальный эквивалент. Если в Example преподаватель вставил кусок кода, моноширинного блока пока нет, но место под него стоит зарезервировать на будущее (потом возможно прикрутим markdown).
