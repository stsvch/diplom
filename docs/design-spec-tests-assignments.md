# ТЗ для дизайнера: редакторы Тестов и Заданий в Course Builder

Документ описывает **сущности, их поля и связи**, а также **сценарии работы преподавателя** с тестами и заданиями. Это база для проектирования макетов в Figma. UI должен следовать общему стилю Course Builder (см. макет `Frontend/CreateCourseScreen.tsx` и `LessonEditor.tsx`): три зоны (структура — редактор — чеклист), inline-сохранение, минимум модалок.

---

## 1. Тест (Test)

### 1.1. Сущность `Test`

Тест — это самостоятельная сущность, прикрепляется к курсу через `CourseItem`.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `Id` | Guid | да | Идентификатор |
| `CourseId` | Guid? | нет | Привязка к курсу (опционально) |
| `Title` | string | да | Название теста |
| `Description` | string? | нет | Описание (показывается студенту до старта) |
| `CreatedById` | string | да | Автор-преподаватель |
| `TimeLimitMinutes` | int? | нет | Лимит времени на прохождение (мин). null = без лимита |
| `MaxAttempts` | int? | нет | Максимум попыток. null = неограниченно |
| `Deadline` | DateTime? | нет | Крайний срок сдачи |
| `MaxScore` | int | вычисляется | Сумма баллов всех вопросов (cached) |
| `ShuffleQuestions` | bool | да, default `false` | Перемешивать порядок вопросов для каждого студента |
| `ShuffleAnswers` | bool | да, default `false` | Перемешивать варианты ответов |
| `ShowCorrectAnswers` | bool | да, default `false` | Показывать студенту правильные ответы после прохождения |
| `CreatedAt` / `UpdatedAt` | DateTime | да | Аудит |

### 1.2. Сущность `Question`

Вопрос принадлежит тесту.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `Id` | Guid | да | Идентификатор |
| `TestId` | Guid | да | Тест, к которому принадлежит |
| `Type` | enum | да | Тип вопроса: `SingleChoice`, `MultipleChoice`, `TextInput`, `OpenAnswer`, `Code`, `Matching` |
| `Text` | string | да | Текст вопроса |
| `Points` | int | да, default `1` | Сколько баллов даёт правильный ответ |
| `OrderIndex` | int | да | Порядковый номер в тесте |
| `GradeType` | enum | да | `Auto` (автопроверка) или `Manual` (ручная проверка преподавателем) |
| `Explanation` | string? | нет | Пояснение к правильному ответу — показывается студенту после прохождения |
| `ExpectedAnswer` | string? | нет | Эталонный ответ для подсказки преподавателю при ручной проверке (для `TextInput`/`Code`) |

### 1.3. Сущность `AnswerOption`

Вариант ответа — есть только у `SingleChoice`, `MultipleChoice`, `Matching`.

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | Guid | Идентификатор |
| `QuestionId` | Guid | Вопрос-родитель |
| `Text` | string | Текст варианта |
| `IsCorrect` | bool | Является ли правильным |
| `OrderIndex` | int | Порядок отображения |
| `MatchingPairValue` | string? | Для типа `Matching` — значение пары |

### 1.4. Типы вопросов

Шесть типов, у каждого свой UX редактирования и прохождения:

| Тип | Что это | Грейдинг | Что редактирует препод | Что видит студент |
|-----|---------|----------|------------------------|-------------------|
| **SingleChoice** | Один правильный ответ из нескольких | Auto | Текст вопроса + варианты + radio «правильный» (только один) | Радиокнопки |
| **MultipleChoice** | Несколько правильных | Auto | Текст + варианты + чекбоксы «правильный» (любое число) | Чекбоксы |
| **TextInput** | Короткий текстовый ответ (одно слово / фраза) | Auto или Manual | Текст + эталонный ответ (для подсказки) | Однострочный input |
| **OpenAnswer** | Развёрнутое эссе | Manual | Только текст вопроса | Большая textarea |
| **Code** | Программный код | Manual | Текст + эталонный код (для проверки) | Code-редактор с подсветкой |
| **Matching** | Сопоставление пар «X — Y» | Auto | Список пар (левая колонка → правая) | Drag-and-drop сопоставление |

### 1.5. Сущности прохождения

| Сущность | Поля | Описание |
|----------|------|----------|
| `TestAttempt` | `Id`, `TestId`, `StudentId`, `AttemptNumber`, `StartedAt`, `CompletedAt`, `Score`, `Status` | Одна попытка студента |
| `TestResponse` | `Id`, `TestAttemptId`, `QuestionId`, `SelectedOptionIds`, `TextAnswer`, `IsCorrect`, `Points`, `TeacherComment` | Ответ студента на конкретный вопрос |

`Status` попытки: `InProgress` / `Completed` / `NeedsReview` (когда есть Manual-вопросы и ждём преподавателя).

После завершения попытки автоматически создаётся запись в **`Grade`** (модуль Grading) с `SourceType = Test`, `Score`, `MaxScore`.

## 2. Задание (Assignment)

### 2.1. Сущность `Assignment`

Задание — это практическая работа, которую студент сдаёт на проверку.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `Id` | Guid | да | Идентификатор |
| `CourseId` | Guid | да | Привязка к курсу |
| `Title` | string | да | Название задания |
| `Description` | string | нет (на этапе создания) | Условие задания |
| `MaxScore` | decimal | да | Максимальный балл |
| `MaxAttempts` | int? | нет | Сколько раз студент может пересдать |
| `Deadline` | DateTime? | нет | Дедлайн сдачи |
| `SubmissionFormat` | enum | да | `Text` / `File` / `Both` — что студент сдаёт |
| `Criteria` | список | нет | Критерии оценивания (см. ниже) |
| `CreatedById` | string | да | Автор |

### 2.2. Сущность `AssignmentCriterion`

Критерий оценивания — preду не просто общий балл, а разбивка по критериям.

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | Guid | |
| `AssignmentId` | Guid | |
| `Title` | string | Название критерия (напр. «Корректность алгоритма») |
| `MaxPoints` | decimal | Сколько даёт этот критерий |
| `OrderIndex` | int | Порядок |

### 2.3. Сущность `AssignmentSubmission`

Отправка студента на проверку.

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | Guid | |
| `AssignmentId` | Guid | |
| `StudentId` | string | |
| `AttemptNumber` | int | |
| `SubmittedAt` | DateTime | |
| `TextAnswer` | string? | Если формат `Text` или `Both` |
| `Attachments` | список | Если формат `File` или `Both` |
| `Status` | enum | `Submitted` / `Reviewing` / `Approved` / `NeedsRework` |
| `Score` | decimal? | Оценка (заполняет преподаватель) |
| `TeacherComment` | string? | Комментарий преподавателя |
| `CriteriaScores` | список | Оценка по каждому критерию (если есть) |

После выставления `Score` создаётся запись в **`Grade`** с `SourceType = Assignment`.

## 3. Связь с курсом — `CourseItem`

В курсе тесты и задания **отображаются как элементы структуры** (`CourseItem`).

`CourseItem` живёт в модуле Courses и содержит:
- `Id`, `CourseId`, `ModuleId` (раздел), `OrderIndex`
- `Type`: `Lesson` / `Test` / `Assignment` / `Resource` / `ExternalLink`
- `SourceId`: ID реальной сущности (например, `Test.Id`)
- `Title`, `Description`, `Status` (`Draft` / `NeedsContent` / `Ready` / `Published`)
- `Points` (для отображения в чеклисте)
- `Deadline`, `AvailableFrom` (могут переопределять собственные у Test/Assignment)

Вся карточка теста в дереве слева в Course Builder — это `CourseItem` с `Type = Test`. При клике справа открывается **встроенный редактор теста**.

## 4. Сценарии работы преподавателя

### 4.1. Создание теста в курсе

1. Препод нажимает «+ Добавить элемент» под разделом → выбирает «Тест».
2. Создаётся пустой `Test` (Title = «Новый тест») + `CourseItem` с `Type = Test`, `Status = NeedsContent`.
3. Карточка теста сразу появляется в нужном разделе и автоматически выбирается.
4. В правой части экрана открывается встроенный редактор теста.

### 4.2. Заполнение теста

Редактор теста состоит из 3 секций:

**A. Шапка теста**
- Бейдж «Тест · в разделе X»
- Большое поле названия (inline edit, как у урока)
- Без чекбокса «обязательный» (тесты всегда учитываются)

**B. Свернутая секция «Настройки теста»**
- Лимит времени (мин) — number, placeholder «Без ограничения»
- Макс. попыток — number, placeholder «Неограниченно»
- Дедлайн — datetime
- Тогглы: Перемешивать вопросы / Перемешивать ответы / Показывать правильные ответы

**C. Список вопросов**

Если вопросов нет — empty state с кнопками-карточками 5 типов вопросов.

Если вопросы есть — каждый отображается отдельной карточкой:
- Шапка карточки: номер вопроса, бейдж типа (с иконкой), input для баллов, кнопка-корзина.
- Текст вопроса (textarea)
- В зависимости от типа:
  - **SingleChoice**: список вариантов с radio-кнопкой «правильный» + кнопка «+ Добавить вариант». Удаление варианта запрещено если остался один.
  - **MultipleChoice**: то же, но чекбоксы (любое число правильных).
  - **TextInput**: textarea «Эталонный ответ» с пометкой что это для подсказки преподавателю.
  - **OpenAnswer**: жёлтая плашка-note «Развёрнутый ответ проверяется вручную преподавателем». Без полей.
  - **Code**: тёмная textarea code-style для эталонного решения.
  - **Matching**: две колонки. Левая — items, правая — соответствие. (Опционально — на этапе MVP можно пропустить.)
- Опциональное `<details>` «Пояснение к ответу» — textarea с пояснением, которое студент увидит после прохождения.

Снизу — кнопка «+ Добавить вопрос» с раскрывающимся picker'ом 5 типов.

### 4.3. Прохождение теста студентом (отдельные макеты)

- Стартовая страница: Title, Description, кол-во вопросов, лимит времени, баллы, кнопка «Начать».
- Один вопрос на экран (Stepper) или все сразу (Scroll) — настройка теста определяет.
- Таймер в углу (если есть лимит).
- Кнопка «Завершить» в конце.
- Экран результатов: общая оценка, разбор вопросов (если `ShowCorrectAnswers`), время прохождения.

### 4.4. Создание задания в курсе

Аналогично тесту: «+ Добавить элемент» → «Задание». Создаётся пустой `Assignment` + `CourseItem`.

### 4.5. Заполнение задания

**A. Шапка**
- Бейдж «Задание · в разделе X»
- Inline-редактируемое название

**B. Настройки задания**
- Описание задания (textarea)
- Дедлайн (datetime)
- Максимальный балл (number)
- Макс. попыток (number, опционально)
- Формат сдачи: переключатель `Text` / `File` / `Both`

**C. Критерии оценивания**

Список criteria-row'ов:
- Название критерия (input)
- Макс. баллов (number)
- Кнопка-корзина

«+ Добавить критерий» внизу.

Если критериев нет — простой `MaxScore` на всё задание.

Если критерии есть — preду оценивает по каждому, итоговая = сумма.

### 4.6. Проверка отправок задания (отдельный экран)

- Список отправок: студент, дата, статус, оценка (если выставлена), кнопка «Проверить».
- Экран проверки: текст/файл студента, поле для оценки (общее или по критериям), комментарий преподавателя, кнопка «Принять» / «Отправить на доработку».

## 5. Состояния и статусы

### 5.1. Статусы `CourseItem`

Применяются и к Test, и к Assignment:

| Статус | Когда | Как выглядит |
|--------|-------|--------------|
| `Draft` | Только что создан, ничего не заполнено | Серая точка |
| `NeedsContent` | Что-то заполнено, но не всё (например, нет вопросов в тесте) | Жёлтый кружок-восклицательный |
| `Ready` | Полностью заполнен и валиден | Зелёная галочка |
| `Published` | Курс опубликован | Зелёная галочка |
| `Archived` | Архивирован | Серый |

Для теста `Ready` = есть хотя бы 1 вопрос с заполненным текстом и правильными ответами (для choice-типов) или эталонным ответом (для Manual).

Для задания `Ready` = есть Description, MaxScore > 0, формат сдачи задан.

### 5.2. Чеклист готовности курса (правая панель)

Показывает все ошибки/предупреждения курса, в том числе:
- «В тесте `<title>` нет вопросов» — клик ведёт на тест
- «У задания `<title>` не указано описание» — клик ведёт на задание
- «У live-занятия `<title>` нет ссылки на встречу» — и т.д.

Каждый пункт чеклиста кликабелен и переводит фокус на проблемный элемент.

## 6. Визуальный стиль

Должен соответствовать общему Course Builder:

| Элемент | Стиль |
|---------|-------|
| Тест (бейдж, акцент) | `orange-500` основной + `orange-50/100` фон |
| Задание | `rose-500` (розовый) основной + `rose-50/100` фон |
| Урок | `indigo-500` |
| Текст | Inter / системный шрифт |
| Скругления | 8-16 px (radius-md, radius-lg, radius-xl) |
| Отступы | 8 / 12 / 16 / 24 (spacing-2 .. spacing-6) |
| Кнопки | Rounded, цветной фон акцентного цвета, лёгкая тень |
| Карточки | Белый фон, 1px border slate-200, левая полоса 3px цветом типа |
| Hover | `translateY(-2px)` или светлый фон акцентного цвета |
| Сохранение | Indicator в TopBar: «Сохранение…» / «Сохранено» / «Ошибка» |

## 7. Что нужно от дизайнера

**Минимальный набор макетов:**

1. **Редактор теста (Course Builder context)** — весь сценарий 4.2 на одном макете:
   - Empty state с picker'ом типов
   - Заполненный тест с 3-4 разными вопросами (по одному примеру каждого типа)
   - Раскрытая секция настроек
2. **Редактор задания** — сценарий 4.5:
   - Пустое задание (только что создано)
   - Заполненное задание с критериями
3. **Состояния** в дереве слева:
   - Тест Draft / NeedsContent / Ready
   - Задание со всеми статусами
4. **Чеклист публикации курса** — права панель с активными ошибками от тестов и заданий.

**Опционально (вторая итерация):**

5. **Прохождение теста студентом** — стартовая страница + один вопрос + результат.
6. **Сдача задания студентом** — форма отправки + история своих попыток.
7. **Проверка отправок преподавателем** — список + детальная страница проверки одной отправки.

## 8. UX-нюансы для дизайнера

- **Без модалок для создания вопросов.** Всё inline. Кликнул «Добавить вопрос» → открылась карточка прямо в списке.
- **Автосохранение.** Кнопок «Сохранить» **нет**. Все изменения уходят на бэк через debounce 800мс.
- **Drag-and-drop для вопросов и вариантов** — желательно, но не критично для MVP.
- **Раскрывающиеся секции** (настройки теста, пояснения к вопросу) — collapsed по умолчанию, не загромождают экран.
- **Empty states** должны быть приветливыми, объяснять что сделать дальше, и сразу давать действие (кнопки 5 типов вопросов).
- **Пустой stub**: только что созданный тест/задание сразу должен быть валидным (статус `NeedsContent`), а не падать с ошибкой валидации. Все обязательные поля заполняются по дефолту.
